# 视频高还原约会邀请设计规格

## 1. 目标与验收标准

本轮以用户提供的 19.6 秒参考视频为唯一视觉与交互基准，替换当前偏重的“档案拼贴”界面。目标不是复刻附图中的纸张、胶带和印章，而是还原视频的粉白黑轻量卡片、可爱小头像、少量花朵点缀，以及“不要”按钮连续逃跑的核心趣味。

验收时应能一眼看出以下特征：

- 首屏是粉色留白背景中的白色黑边圆角卡，不再出现文件夹标签、牛皮纸、胶带、回形针、纸张噪点和深色桌面。
- 首屏文案为“可以和我一起约会嘛？！”；主按钮为粉色“愿意”，副按钮为白色“不要”。
- 桌面端鼠标一靠近“不要”就逃跑，移动端手指按下时逃跑；按钮每次都换到新位置和新文案，连续追逐不会跳到认真拒绝页，也不会出现固定的“今天先不约”。
- 点击“愿意”后先进入“等下，你真的点了愿意？”二次确认，再进入日期、时间、食物和结果页。
- 食物页恢复为接近视频的 3 列选择网格，成功页使用简洁的日期、时间、菜单摘要卡。

## 2. 方案比较与最终选择

### 方案 A：视频结构高还原，复用现有毛绒角色作为小头像（采用）

完整采用视频的版式、色板、按钮、阴影、留白和流程，只把视频里的法斗头像替换为项目已有的毛绒角色小头像。优点是还原度最高、改动边界清楚，也能保留本项目的识别度。

### 方案 B：视频骨架，加大毛绒角色占比

保持视频卡片结构，但让角色继续以半屏插画出现。优点是品牌感强，缺点是会再次挤压留白，容易回到附图那种“画面很满”的状态。

### 方案 C：继续优化档案拼贴

只调整当前纸张、印章和角色比例。开发量最小，但无法解决用户指出的“视觉不如视频”和“交互不够还原”两个根本问题，因此不采用。

## 3. 视觉系统

### 色彩

- 页面底色：`#F7D7E6`，辅以非常轻的白色径向渐变。
- 主卡背景：`#FFFDFB`。
- 主粉色：`#EC4BA8`；按下或选中状态使用 `#D93696`。
- 文字与描边：`#171317`。
- 次级文字：`#766C73`。
- 极少量点缀：浅黄 `#FFE58B`、淡粉 `#FFD3E8`。

### 字体与排版

- 字体栈：`PingFang SC`, `Hiragino Sans GB`, `Microsoft YaHei`, sans-serif。
- 页面大标题：移动端 `34–40px`，字重 `800–900`，行高 `1.08`，居中。
- 正文：`14–16px`，字重 `600`，行高 `1.5`。
- 辅助标签：`11–12px`，字重 `700`。
- 不使用手写体、复古印章体或明显的纸张字体。

### 卡片与按钮

- 移动端舞台宽度为视口宽度，核心卡片宽度为 `calc(100% - 32px)`，最大 `390px`。
- 核心卡片圆角 `28px`，黑色描边 `3px`，硬阴影 `6px 8px 0 #171317`。
- 按钮高度 `52–56px`，圆角 `999px`，黑色描边 `2.5px`，硬阴影 `4px 6px 0 #171317`。
- 首屏只保留 3–5 朵小花与少量小心心，不增加纹理背景、装饰标签或大面积插画。
- 现有毛绒角色被裁进 `78–92px` 的小头像框，头像框使用白底、黑边、粉色偏移阴影。

## 4. 页面与交互流程

### 4.1 首屏邀请

首屏主体保持垂直居中。结构从上到下为：小头像、标题“可以和我一起约会嘛？！”，副文案“系统检测到：对方已经紧张到开始写网页了。”，按钮互动区域。

“愿意”按钮始终固定在互动区域左侧或下方主位。“不要”按钮由 Framer Motion 控制坐标，不用整页切换动画，也不同时叠加 CSS 位移动画。

拒绝按钮使用 6 个确定位置循环，位置以互动区域为坐标：

1. 初始：主按钮右侧。
2. 第一次追逐：卡片右缘，允许按钮约三分之一悬出主卡，但不能超出视口。
3. 第二次追逐：标题右侧的小花附近。
4. 第三次追逐：按钮区右侧。
5. 第四次追逐：互动区域左上。
6. 第五次追逐：互动区域左下。
7. 后续继续循环第 2–6 个位置，不得连续两次落到同一位置。

按钮文案随追逐轮换：“不要”→“不要哇”→“点不到吧”→“不要嘛”→“你抓不到”→“别点我啦”。桌面端使用 `pointerenter` 触发，移动端使用 `pointerdown` 并阻止随后的点击，键盘操作使用 click 作为兜底；相邻触发小于 `260ms` 时只计算一次，避免同一次触摸跳两步。每次位移约 `180–260ms`，到达后使用 `0.96 → 1.04 → 1` 的轻微回弹。按钮可以越过主卡边框，但始终完整留在 360、390、430 像素宽的视口内。

“不要”按钮的点击只更新 `declineStep`，页面 phase 始终为 `INTRO`。新流程不再进入 `SERIOUS_CHOICE` 或 `DECLINED`；旧 phase 仅为兼容已有本地存档保留。

### 4.2 二次确认

点击“愿意”后，主按钮先产生一次短促按压和心形反馈，再进入二次确认卡。页面显示小型惊讶角色、标题“等下，你真的点了愿意？”，副文案“我都已经准备好被你点‘不要’了。”，以及一个粉色按钮“好啦好啦，我愿意”。

保留一个弱化文本入口“刚刚手滑了”，点击回到首屏。该入口不与主按钮并列，不抢占视觉焦点。

### 4.3 日期与时间

页面标题为“所以…你什么时候有空？”。使用原生日期输入、时间选择控件和可选备注。输入框为白底黑边圆角矩形，选中时只改变为粉色描边与浅粉底，不使用票据、网格纸或印章。

日期和时间未完成时，主按钮保持禁用；完成后按钮变为粉色。返回入口回到二次确认页。

### 4.4 食物选择

页面标题为“我们吃点什么？”，副文案为“挑一个今天的约会氛围。”。使用 3 列网格，选项为：披萨、寿司、火锅、烤肉、早茶、拉面、麻辣烫、小龙虾、烧烤、其他。

每个选项只包含一个简洁 emoji/图标和文字，白底、黑边、硬阴影。选中项改为浅粉底、主粉描边，并轻微上浮。点击选项后停留约 `480ms` 展示选中反馈，然后直接进入轻量生成状态；不再增加视频里没有的底部确认按钮。

### 4.5 生成中与成功页

生成中页面只保留小角色、跳动的心和 1–2 行状态文案，不再使用飞行信封、档案装订等复杂叙事。

成功页显示小头像、标题“真开心你没有拒绝～我会准时来接你！”，摘要文字，以及一个 2×2 的信息卡：日期、时间、菜单，第四格可留作备注。底部保留分享、保存和重新查看功能，但视觉统一为视频的粉白黑按钮体系。

分享链接打开的页面复用同一套成功卡样式，避免回到旧档案风。

## 5. 组件与数据流

- `InvitationFlow` 继续作为单一流程入口，只在 `phase` 改变时执行页面转场；`declineStep` 改变不能重挂整个首屏。
- `state-machine` 负责流程：`INTRO → SECOND_CONFIRM → SCHEDULE → FOOD → SUBMITTING → SUCCESS`。
- `IntroScene` 只负责首屏布局、按钮逃跑坐标和点击反馈；逃跑文案与坐标采用常量数组，便于测试。
- `SceneFrame` 只提供粉色舞台、白色主卡和少量装饰，不再包含档案品牌头、标签页或回形针。
- `ScheduleScene` 保留现有日期、时间、备注数据接口。
- `FoodScene` 扩展 `FoodId` 配置，选中后先写入状态，再由单一计时器触发提交；组件卸载时必须清理计时器。
- `SubmittingScene`、`SuccessScene`、`SharedPlanScene` 保留现有提交、分享、复制链接和打印逻辑，只替换表现层。
- 本轮不新增依赖、不新增后端接口、不改分享链接编码协议。

## 6. 本地存档兼容

当前本地存储会恢复旧 phase。为避免老用户打开新版后直接落入旧拒绝页，本轮升级存储 key；旧存档不迁移，首次进入新版从首屏开始。分享链接不依赖该本地存储，保持可用。

旧的 `walk`、`exhibit` 分享值保留只读兜底标签，避免历史链接显示空白；新食物选择不再生成这两个值。

## 7. 错误与边界处理

- 360px 宽设备上，拒绝按钮可以悬出主卡边框，但必须完整位于视口内，不能被页面裁切。
- 用户开启“减少动态效果”时，按钮仍会换位置，但动画时长压缩到近乎即时。
- 原生日期选择器使用当天作为最小日期；未完成日期或时间时不允许进入食物页。
- 提交接口失败时沿用当前前端完成流程，不在本轮引入错误页；分享取消时继续显示现有的温和提示。
- 对旧 phase 的兼容页面统一套用新 `SceneFrame`，但新用户流程不再能进入这些页面。

## 8. 测试与视觉验收

### 单元测试

- “愿意”进入二次确认，确认后才进入日程。
- 连续点击“不要”至少 10 次，phase 始终为 `INTRO`，step 按预定序列循环。
- 完成日期、时间和食物后仍可提交并进入成功页。

### 端到端测试

- 验证首屏标题、按钮文案和稳定存在的“愿意”按钮。
- 桌面端移动鼠标、移动端触发 `pointerdown` 追逐“不要”至少 6 次，验证 `data-dodge-step` 和按钮边界框至少出现 5 个不同位置，且不出现认真拒绝页。
- 验证完整流程：愿意 → 二次确认 → 日期/时间 → 食物 → 成功。
- 验证刷新后恢复新版未完成流程，分享链接仍可打开成功卡。

### 视觉验收

- 重新生成 390×844 的首屏、3 次逃跑、二次确认、日期、食物、成功页截图。
- 补充 360×800、430×932 和 1280×900 的溢出检查。
- 对照视频检查：粉色留白、白卡占比、黑边与硬阴影、头像大小、按钮布局、花朵数量、九宫格密度。
- `npm test`、`npm run lint`、`npm run build`、`npm run e2e` 全部通过后才可交付。

## 9. 明确不做

- 不使用四张附图作为背景或逐屏复刻附图。
- 不生成新的大型插画，也不新增图片生成依赖。
- 不加入地图、地点推荐、聊天、登录或后端通知。
- 不保留首屏固定拒绝入口，不在连续逃跑后强制切换到认真拒绝流程。
- 不重写分享协议和提交接口。
